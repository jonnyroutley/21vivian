This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

"21vivian" / "Boys' House" — a small app for a shared house. Features: peer reviews, events with RSVPs, household energy usage (Octopus Energy), an AI chat bot with per-housemate personas (Gemini), and push notifications ("bingbong"). A two-package monorepo under `packages/` with no root tooling — run commands from inside each package.

- `packages/api` — Rust HTTP API (Poem + poem-openapi), SeaORM over Postgres (Neon), S3 uploads, Gemini, Pushsafer.
- `packages/frontend` — Next.js 14 (App Router) using Bun, Biome, Tailwind + shadcn/ui, TanStack Query.

## Commands

### Frontend (`packages/frontend`, Bun, Node v22.3.0)
- `bun run dev` — dev server on **port 8080**
- `bun run build` / `bun run start`
- `bun run lint` — Biome check + autofix (formatter and linter; tab indent, double quotes)
- `bun run types` — regenerate `src/client/schema.d.ts` from `../api/spec.yml` (see contract flow below)

### API (`packages/api`, Rust 1.88, Cargo workspace)
- `cargo run` — starts the server; runs `Migrator::up` automatically on boot
- `cargo build --locked --release`
- `cargo fmt` / `cargo clippy`
- Migrations (run inside `packages/api/migration`): `cargo run -- generate NAME`, `cargo run -- up`, `cargo run -- down`, `cargo run -- fresh`, `cargo run -- status` (full list in `packages/api/migration/README.md`)
- Docker: `docker compose up --build` (from `packages/api`)

The API binds to `API_BASE_URL` (e.g. `0.0.0.0:8000`). Swagger UI at `/docs`, OpenAPI YAML at `/docs/spec`.

## Architecture

### API ↔ frontend contract (important)
The OpenAPI spec is the source of truth and is **generated by the running Rust server**, not hand-written. `routes::app_routes` builds the `OpenApiService` from the route structs and calls `save_spec` to write `packages/api/spec.yml` on every startup. The frontend then runs `bun run types` to turn that spec into typed `paths`/`components` in `src/client/schema.d.ts`. So: change a Rust route → restart the API to refresh `spec.yml` → run `bun run types` in the frontend. Do not edit `schema.d.ts` by hand.

### API structure (Cargo workspace: `.`, `entity`, `migration`)
- `src/main.rs` — wires everything: connects DB, runs migrations, constructs the three services, then `routes::app_routes(...)`. Services are injected into each route struct (each holds `Arc<DatabaseConnection>` and whatever services it needs).
- `src/routes/*.rs` — one struct per domain (`ReviewApi`, `EventApi`, `UploadApi`, `InfoApi`, `NotifyApi`, `ChatApi`) with an `#[OpenApi] impl`. Request/response types are `#[derive(Object)]` / `#[derive(ApiResponse)]` with explicit status-coded variants (e.g. `Ok(Json<...>)`, `InternalServerError`).
- `src/services/` — external integrations behind plain structs: `upload_service` (`S3Service`, aws-sdk-s3), `notification_service` (`PushsaferService`, reqwest), `ai_service` (`AiService`, Gemini via reqwest; holds per-`Housemate` persona contexts).
- `entity/` — SeaORM models (`reviews`, `events`, `attendees`, `uploads`).
- `migration/` — SeaORM migrations; register new ones in `migration/src/lib.rs`.

### Frontend structure (`src/`, `@/` → `src/`)
- `app/` — App Router pages, one folder per feature (`reviews`, `events`, `energy`, `chat`, `gotm`, `bingbong`, `landing`). Co-located components live in the feature folder.
- `actions/` — `"use server"` server actions that call the API. They `fetch(`${config.apiBaseUrl}/...`)` and `revalidatePath` after mutations. Types are derived from the generated schema (e.g. `components["schemas"]["EventDto"]`).
- `actions/energy.ts` is the exception: it calls the **Octopus Energy API directly** (not our Rust API), with hardcoded meter IDs and a gas m³→kWh conversion factor.
- `components/ui/` — shadcn/ui primitives (config in `components.json`, base color stone, CSS variables). `lib/utils.ts` `cn()` for class merging.
- `lib/config.ts` — Zod-validated env config (`apiBaseUrl`, `octopusApiKey`).

## Config & deploy
- Frontend env: `NEXT_PUBLIC_API_BASE_URL`, `OCTOPUS_API_KEY` (`.env.local`).
- API env: `DB_URL`, `API_BASE_URL`, AWS (`AWS_ACCESS_KEY_ID`/`SECRET`/`REGION`), `PUSHSAFER_KEY`, `GEMINI_API_KEY`, `GEMINI_BASE_URL` (loaded via dotenvy from `packages/api/.env`).
- API deploys via Cloud Build (`packages/api/cloudbuild.yaml`) to GCR (`gcr.io/vivian-472117/...`); multi-stage Alpine `Dockerfile`. Frontend deploys on Vercel.
